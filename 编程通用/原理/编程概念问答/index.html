原语是什么意思？ 

- 在计算机科学中，原语通常是指操作系统提供的一些基本的、不可分割的操作，这些操作作为系统调用供用户程序使用。如进程控制、信号、文件操作等可以被视为原语。


- 在编程语言中，原语也可以指最基本的操作或函数，它们是构建更复杂程序的基础。

什么是组件的连接字（Component Connector）？

  • 一个软件架构和设计模式中的术语，形容不同组件或模块之间相互连接和通信的机制或接口

    • 接口（Interface）：
      • 在面向对象编程中，接口定义了一组方法和属性，组件通过实现这些接口来进行通信。
    • API（应用程序编程接口）：
      • API是一组预定义的函数、协议和工具，用于构建软件应用。组件通过调用API来实现交互。
    • 服务（Service）：
      • 在服务导向架构（SOA）或微服务架构中，服务作为独立的业务功能单元，组件通过服务调用来交互。
    • 消息队列（Message Queue）：
      • 组件通过发送和接收消息来进行异步通信，消息队列是这种通信方式的典型实现。
    • 事件（Event）：
      • 组件可以基于事件来通信，其中某个组件触发事件，其他组件监听并响应这些事件。
    • 管道（Pipe）：
      • 在某些系统设计中，管道可以作为进程间通信的手段，允许数据从一个进程流向另一个进程。
    • 套接字（Socket）：
      • 网络编程中，套接字用于在网络中的不同主机上的组件之间建立通信。
    • 数据库（Database）：
      • 组件可以通过数据库来共享数据，数据库作为一个共享的存储机制，允许组件进行读写操作。
    • 文件系统（File System）：
      • 组件可以通过读写文件来交换数据，文件系统在这里充当连接字的角色。
    • 通信协议（Communication Protocol）：
      • 在网络通信中，如TCP/IP、HTTP等协议定义了数据传输的规则，是组件间通信的基础。
    • 中间件（Middleware）：
      • 中间件提供了一种在不同系统或组件之间传递数据的方法，它可以处理不同系统之间的通信细节。

  • MQTT Broker 是一种服务器，它负责接收来自发布者（Publishers）的消息，并将这些消息分发给订阅了相应主题（Topics）的订阅者（Subscribers）。它的主要功能包括：

    1. 消息路由：接收发布者发送的消息，并根据订阅者的订阅主题将消息路由到正确的订阅者。

    2. 会话管理：维护客户端连接的会话信息，包括连接状态、订阅信息和消息队列。

    3. 消息存储：存储持久化消息，以便在订阅者不可用时保留消息，并在订阅者恢复连接时传递消息。

    4. 质量保证：根据 QoS（Quality of Service）等级，确保消息按规定的可靠性传递。

      MQTT Broker 的工作原理

      1. 客户端连接：客户端（包括发布者和订阅者）通过网络连接到 Broker。连接建立后，客户端可以发布消息或订阅主题。
      2. 消息发布：发布者将消息发送到 Broker，并指定一个或多个主题。消息可以携带不同的 QoS 等级，决定消息的传递可靠性。
      3. 消息订阅：订阅者向 Broker 订阅感兴趣的主题。订阅请求可以指定 QoS 等级，决定订阅者希望接收消息的可靠性。
      4. 消息路由和分发：Broker 接收到消息后，根据订阅者的订阅信息，将消息分发给相应的订阅者。

      QoS（服务质量）等级

      MQTT 定义了三个 QoS 等级，以满足不同的可靠性需求：

      • QoS 0：至多一次（At most once），消息发送但不确认，不保证消息到达（“最佳努力”传递）。
      • QoS 1：至少一次（At least once），消息发送并确认，确保消息至少到达一次，但可能会有重复。
      • QoS 2：仅一次（Exactly once），消息发送并通过四步握手确认，确保消息仅到达一次，最可靠但开销最大。

      常见的 MQTT Broker 实现

      有许多开源和商业的 MQTT Broker 实现，以下是一些常见的 MQTT Broker：

      • Mosquitto：一个轻量级的开源 MQTT Broker，适合嵌入式设备和小型物联网项目。
      • EMQX：一个高性能的开源 MQTT Broker，支持大规模并发连接，适合大型物联网项目。
      • HiveMQ：一个商业 MQTT Broker，提供企业级功能和支持。
      • Eclipse Paho：Eclipse 基金会下的一个开源 MQTT 客户端库和 Broker 项目。

      使用场景

      MQTT Broker 被广泛应用于物联网（IoT）场景中，包括但不限于：

      • 智能家居：设备之间的通信和控制，如智能灯、智能插座等。
      • 工业自动化：机器和传感器之间的数据传输和监控。
      • 车联网：车辆数据的采集和实时传输。
      • 医疗健康：医疗设备的数据传输和监控。

      总结

      MQTT Broker 是 MQTT 协议的核心组件，负责管理消息的传递和分发。通过支持发布/订阅模式、QoS 等级和会话管理，MQTT Broker 提供了高效可靠的消息传输机制，适用于各种物联网应用场景。选择合适的 MQTT Broker 取决于项目的规模、性能要求和特定功能需求。

什么是安装证书

  • 安装证书通常指的是在计算机或设备上添加数字证书的过程。数字证书是一种用于加密和验证通信的安全性工具，通常用于加密和保护网络通信、网站身份验证等方面。在安装证书的过程中，用户将数字证书文件添加到其操作系统、浏览器或应用程序的信任存储中，以确保与其他实体的安全通信。

    安装证书的常见场景

    1. 网站身份验证：Web 浏览器通常会使用数字证书来验证网站的身份。当用户访问一个使用 HTTPS 协议的网站时，网站会向浏览器发送其数字证书，浏览器会验证证书的有效性，并确定是否与信任的证书颁发机构相关联。
    2. 电子邮件加密：在电子邮件通信中，数字证书可以用于加密和签名邮件，确保邮件内容的保密性和完整性。
    3. VPN 连接：VPN（Virtual Private Network）连接通常需要数字证书来验证用户的身份和加密通信。
  1. 客户端身份验证：在某些系统中，客户端需要提供数字证书来验证其身份，以访问受限资源或服务。

安装证书的步骤 

安装数字证书通常涉及以下步骤：
  1. 获取证书：用户需要获取数字证书文件，通常是由可信任的证书颁发机构（CA）签发的。这些证书可以是网站的 SSL 证书、电子邮件签名证书等。 2. 导入证书：用户需要将数字证书导入其操作系统、浏览器或应用程序的证书存储中。导入证书的方法取决于所使用的操作系统和软件。
  2. 信任证书：一旦证书被导入，用户可能需要手动将其标记为受信任的证书。这样做可以确保系统或软件信任证书颁发机构签发的证书，并在与其他实体通信时使用它们。 4. 配置选项：有时，用户可能需要在操作系统、浏览器或应用程序中配置一些选项，以确保数字证书被正确地使用和管理。
### 安全考虑

在安装数字证书时，需要注意以下安全考虑：

  • 来源可信性：确保从可信任的来源获取数字证书，避免使用来自不可信任或未知来源的证书。

    • 验证证书有效性：在安装证书之前，用户应该验证证书的有效性，包括证书的有效期、签发者等信息。

  • 保护私钥：如果证书包含私钥，则需要确保私钥的保密性，以防止未经授权的访问或使用。

    • 定期更新：定期检查和更新证书，以确保其仍然有效，并且与安全最佳实践保持一致。

    通过正确地安装和管理数字证书，用户可以增强其网络通信的安全性和可信度，并确保与其他实体的安全通信。

创造者：丹尼斯·里奇（Dennis Ritchie） 初衷：C语言是在1970年代早期由贝尔实验室的丹尼斯·里奇开发的，目的是为开发UNIX操作系统提供一种高效且灵活的语言。C语言继承了B语言的某些特性，并增加了类型系统以提高编程的安全性和表达能力。 评价：丹尼斯·里奇认为，C语言成功地达到了他的目标，即提供了一种既接近硬件又适合高级程序设计的语言。它的简单性和效率使其成为系统编程和嵌入式编程的主流语言之一。

2. Java

创造者：詹姆斯·高斯林（James Gosling） 初衷：Java语言最初于1990年代初在Sun Microsystems开发，目标是创建一种跨平台的编程语言，能够在不同的设备和操作系统上运行。Java的设计哲学是“写一次，运行到处”（Write Once, Run Anywhere），并且注重安全性和稳定性。 评价：詹姆斯·高斯林对Java的评价是，它成功地实现了跨平台的目标，并成为了互联网时代的关键编程语言之一。尽管随着时间推移，Java面临了一些新的挑战和竞争，但其核心理念和影响力依然强大。

3. Python

创造者：吉多·范罗苏姆（Guido van Rossum） 初衷：Python语言于1980年代末至1990年代初由吉多·范罗苏姆开发，目的是创建一种易于阅读和使用的编程语言，能够帮助程序员快速开发和调试代码。Python强调简洁和可读性，力求减少程序员的认知负担。 评价：吉多·范罗苏姆对Python的发展表示满意，他认为Python在保持简单和易用的同时，已经发展成为一个功能强大的语言，广泛应用于数据科学、人工智能、Web开发等领域。

4. JavaScript

创造者：布兰登·艾克（Brendan Eich） 初衷：JavaScript于1995年由布兰登·艾克在Netscape公司开发，目标是为Web浏览器添加一种轻量级的脚本语言，以便于处理用户交互和动态内容。JavaScript的设计注重简便和灵活性。 评价：布兰登·艾克认为，尽管JavaScript起初面临许多批评和挑战，但它已经成长为一种重要的编程语言，推动了Web技术的发展。如今，JavaScript不仅在客户端编程中占据主导地位，还扩展到了服务器端（如Node.js）。

5. C++

创造者：比雅尼·斯特劳斯特鲁普（Bjarne Stroustrup） 初衷：C++是在1980年代由比雅尼·斯特劳斯特鲁普开发的，目的是在C语言的基础上增加面向对象编程的特性，从而提高程序的模块化和可维护性。C++兼顾了系统编程的效率和高级程序设计的灵活性。 评价：比雅尼·斯特劳斯特鲁普认为，C++成功地达到了他的设计目标，并且在工业界和学术界得到了广泛应用。他对C++的演变和持续发展表示欣慰，并认为它在现代软件开发中仍然具有重要地位。

6. Ruby

创造者：松本行弘（Yukihiro “Matz” Matsumoto） 初衷：Ruby语言于1990年代中期由松本行弘开发，目标是创建一种简洁且强大的编程语言，使程序员在编程时感到愉悦和高效。Ruby融合了多种编程范式，强调优雅和简便。 评价：松本行弘对Ruby的成功感到高兴，尤其是在Web开发领域（如Ruby on Rails的影响）。他认为Ruby实现了他当初的设计理念，让编程变得更有乐趣和创造性。

7. Swift

创造者：克里斯·拉特纳（Chris Lattner） 初衷：Swift语言由克里斯·拉特纳在苹果公司主导开发，发布于2014年，目的是取代Objective-C，提供一种现代、安全、快速的编程语言，适用于iOS和macOS应用开发。Swift结合了现代编程语言的最佳特性，注重安全性和性能。 评价：克里斯·拉特纳对Swift的评价非常正面，他认为Swift在简化开发过程、提高代码安全性和执行性能方面表现出色。Swift的快速普及和广泛应用表明它达到了预期的目标。

这些编程语言的创造者普遍认为，他们的语言在实现最初的设计目标方面取得了成功，并且在各自的应用领域内产生了深远的影响。尽管随着时间的推移，每种语言都面临新的挑战和竞争，但其核心理念和影响力依然显著。

什么是构析函数（Destructor）？

析构函数是类的特殊方法，当对象被垃圾回收时调用。它用于清理资源（如关闭文件、释放内存）。析构函数的名称与类名相同，并且前面加上波浪号（~）。

特点：

  • 名称与类名相同，前面加上波浪号（~）。
  • 没有参数和返回类型。
  • 每个类最多只有一个析构函数，不能重载。
  • 由垃圾回收器（GC）调用，不确定何时调用。

正则表达式的语法是什么样的？

正则表达式由普通字符（例如字母和数字）和特殊字符组成。特殊字符包括：

  • .：点字符可以匹配任何单个字符（除了换行符）。
  • *：星号表示前面的元素可以出现零次或多次。
  • ^: 字符串的开头
  • $: 字符串的结尾
  • +：加号表示前面的元素至少出现一次。
  • ?：问号表示前面的元素可以出现零次或一次。
  • []：方括号定义一个字符集合，匹配其中的任意一个字符。
  • ()：圆括号用于分组，也用于捕获匹配的文本。
  • |：竖线表示逻辑“或”，匹配两个或多个选项中的一个。
  • \d：匹配任意数字，等同于 [0-9]。
  • \w：匹配任意字母数字字符，包括下划线。
  • \s：匹配任何空白字符（空格、制表符、换行符等）。

什么是回调函数？

回调函数（Callback Function）是一种编程技术，是指将一个函数作为参数传递给另一个函数，当某些特定事件发生或某个操作完成时，由这个函数（即回调函数）被调用，从而实现动态执行逻辑。

通俗地讲，回调函数就像是一种“预约机制”，你告诉某个函数：“一旦发生某件事情，记得调用我传给你的这个函数。”

回调函数的特点

  1. 延迟执行：回调函数不是立即执行，而是在某个事件发生或条件满足后才被调用。
  2. 动态行为：主函数的行为可以根据传入的回调函数不同而发生变化。
  3. 解耦设计：通过回调函数，可以将主逻辑与特定行为分离，增强代码的可扩展性。

回调函数的应用场景

  1. 异步操作

    ：

    • 例如文件读取完成后，通知用户数据已经准备好。

  2. 事件驱动编程

    ：

    • 鼠标点击、按键触发等。

  3. 算法设计

    ：

    • 例如排序算法中自定义比较逻辑。

  4. 框架与库设计

    ：

    • 通过回调函数，用户可以在库函数执行时插入自己的逻辑。

C# 中的回调函数实现

在 C# 中，回调函数通常通过以下三种方式实现：

  1. 委托（Delegate）
  2. 匿名函数（Anonymous Method）和 Lambda 表达式
  3. 接口（Interface）

1. 使用委托实现回调

委托是 C# 中的一个类型，用于封装方法。它是实现回调函数最常见的方式。

using System;

class Program
{
    // 定义一个委托
    public delegate void CallbackDelegate(string message);

    // 主函数：接受回调函数
    public static void DoSomething(CallbackDelegate callback)
    {
        Console.WriteLine("开始执行操作...");
        // 模拟操作完成后调用回调函数
        callback("操作已完成！");
    }

    static void Main(string[] args)
    {
        // 定义回调函数
        CallbackDelegate myCallback = (message) => Console.WriteLine($"回调消息：{message}");

        // 将回调函数传递给主函数
        DoSomething(myCallback);
    }
}

using System;

interface ICallback
{
    void OnComplete(string message);
}

class Worker
{
    private readonly ICallback _callback;

    public Worker(ICallback callback)
    {
        _callback = callback;
    }

    public void DoWork()
    {
        Console.WriteLine("正在工作...");
        // 模拟工作完成后调用回调
        _callback.OnComplete("工作完成，接口回调成功！");
    }
}

class Program : ICallback
{
    // 实现回调接口
    public void OnComplete(string message)
    {
        Console.WriteLine($"回调收到消息：{message}");
    }

    static void Main(string[] args)
    {
        // 创建回调实现类
        Program program = new Program();

        // 创建 Worker 并传入回调
        Worker worker = new Worker(program);

        // 执行任务
        worker.DoWork();
    }
}

总结

  • 回调函数是通过动态传递逻辑来实现程序灵活性和解耦的重要工具。
  • 在 C# 中，回调函数可以通过委托、Lambda 表达式、接口等方式实现。
  • Action 和 Func 提供了更加简洁的回调机制，非常适合现代开发场景。
  • 根据需求选择合适的实现方式，委托适合简单场景，接口适合复杂设计，而 Action 和 Func 更加高效便捷。

抽象类和接口的区别是什么？

接口只规定不实现，抽象类可以实现，而且还带访问封装，接口没有封装。

设计理念 接口的设计理念： • 契约导向：接口强调的是行为契约，任何实现接口的类都必须提供接口中定义的方法。 • 解耦和灵活性：接口使得代码更加解耦和灵活，便于单元测试和依赖注入。 抽象类的设计理念： • 代码复用：抽象类允许在基类中提供一些默认的实现，从而减少代码重复。 • 层次结构：抽象类适用于具有层次结构的场景，提供了一种在基类和派生类之间共享代码的方式。 选择指南 • 使用接口：当你需要定义一组不相关类的共同行为，或者需要实现多重继承时。 • 使用抽象类：当你需要为一组相关类提供一个共同的基类，并且希望在基类中提供一些默认的实现时。

什么是哈希加盐?

**加盐（Salting）*就是给原始密码*添加一段随机字符串，然后再进行哈希，以增加破解的难度。

plaintext复制编辑原始密码：123456
随机盐：  x7!@K2

加盐后：  "123456x7!@K2"
哈希值：  MD5("123456x7!@K2") => 9f1a3e...（不同了）
  • 盐是每个用户随机生成的，并和哈希值一起存储在数据库中。
  • 即使两个用户用相同密码，因为盐不同，最终哈希值也不同。

✅ 四、加盐哈希的好处

问题 加盐能解决吗？ 说明
彩虹表攻击 ✅ 防止 因为每次加盐都不同，彩虹表无法预制所有组合
相同密码哈希相同 ✅ 防止 即使密码一样，加了不同的盐也会得出不同哈希
被盗哈希后能反推密码 ❌ 不能完全防止 加盐只是增加破解难度，不能让哈希变得可逆
