各框架的渲染方式对比
WPF (Windows Presentation Foundation)
┌─────────────────────────────────────────────────────────┐
│  WPF 渲染架构                                            │
├─────────────────────────────────────────────────────────┤
│  XAML → 视觉树 → 渲染树 → DirectX 9 → GPU              │
│                                                         │
│  特点：                                                  │
│  - 基于 DirectX 9 (不是 GDI)                            │
│  - 有保留模式 (Retained Mode) 渲染                     │
│  - 自动处理重绘、动画、变换                            │
│  - 不能直接用 GDI 混合绘制                             │
└─────────────────────────────────────────────────────────┘
// WPF - 你声明 UI，框架负责渲染
<StackPanel>
    <Button Content="Click Me" />
    <TextBlock Text="Hello" />
</StackPanel>
// 底层：WPF 把这些转换为 DirectX 调用
---
Avalonia
┌─────────────────────────────────────────────────────────┐
│  Avalonia 渲染架构                                       │
├─────────────────────────────────────────────────────────┤
│  Avalonia 自研渲染引擎                                   │
│  ├─ 跨平台抽象层                                         │
│  ├─ 支持 DirectX / OpenGL / Metal                       │
│  └─ 也可软件渲染 (CPU)                                  │
│                                                         │
│  特点：                                                  │
│  - 类似 WPF 但跨平台                                     │
│  - 即时模式 (Immediate Mode) 渲染                       │
│  - Skia 作为可选后端                                     │
└─────────────────────────────────────────────────────────┘
---
Qt
┌─────────────────────────────────────────────────────────┐
│  Qt 渲染架构                                             │
├─────────────────────────────────────────────────────────┤
│  QPainter → 后端抽象                                     │
│  ├─ Windows: Direct2D / OpenGL / GDI                   │
│  ├─ macOS: Core Graphics / Metal                       │
│  ├─ Linux: X11 / Wayland / OpenGL                      │
│  └─ 软件渲染 (Raster)                                   │
│                                                         │
│  Qt Quick: 基于场景图 + OpenGL/DirectX                 │
└─────────────────────────────────────────────────────────┘

自绘引擎 (Tsoding 风格)
┌─────────────────────────────────────────────────────────┐
│  自绘引擎架构                                            │
├─────────────────────────────────────────────────────────┤
│  你的代码 → 直接调用图形 API → GPU                     │
│                                                         │
│  可选路径：                                              │
│  ├─ Win32 API + GDI (最简单，CPU 渲染)                  │
│  ├─ Win32 API + Direct2D (现代，硬件加速)              │
│  ├─ Win32 API + OpenGL (跨平台，硬件加速)              │
│  ├─ Win32 API + DirectX 11/12 (Windows 专属)           │
│  └─ 纯 framebuffer + 自己画像素 (最底层)               │
│                                                         │
│  特点：                                                  │
│  - 无中间层，性能最优                                    │
│  - 所有逻辑自己实现 (文本/布局/事件)                   │
│  - 开发成本最高                                          │
└─────────────────────────────────────────────────────────┘
---
关键概念辨析
保留模式 vs 即时模式
┌──────────────────────────────────────────────────────────┐
│  保留模式 (Retained Mode) - WPF/Silverlight             │
├──────────────────────────────────────────────────────────┤
│  你：创建对象树 (Button, TextBlock...)                   │
│  框架：维护场景图，自动处理重绘                          │
│                                                         │
│  优点：开发简单，自动优化                                │
│  缺点：黑箱，难以精细控制                                │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│  即时模式 (Immediate Mode) - OpenGL/自绘                │
├──────────────────────────────────────────────────────────┤
│  你：每帧手动绘制一切                                     │
│  框架：只负责执行你的绘制命令                            │
│                                                         │
│  优点：完全控制，性能可优化                              │
│  缺点：每帧都要重绘，代码量大                            │
└──────────────────────────────────────────────────────────┘
// 保留模式 (WPF)
<Button Content="Click" />  // 创建后不用管，框架自动重绘
// 即时模式 (OpenGL)
while (running) {
    glClear(GL_COLOR_BUFFER_BIT);
    drawButton(x, y, w, h, "Click");  // 每帧手动绘制
    swapBuffers();
}

自绘引擎的真实代码示例
Tsoding 风格 (Win32 + GDI)
// 完全自绘，无 UI 框架
#include <windows.h>
void draw_button(HDC hdc, int x, int y, int w, int h, const char* text) {
    // 自己画矩形
    RECT rect = {x, y, x+w, y+h};
    FillRect(hdc, &rect, (HBRUSH)GetStockObject(GRAY_BRUSH));
    FrameRect(hdc, &rect, (HBRUSH)GetStockObject(BLACK_BRUSH));
    
    // 自己画文字
    TextOut(hdc, x+5, y+5, text, strlen(text));
}
LRESULT CALLBACK WndProc(HWND hwnd, UINT msg, WPARAM wParam, LPARAM lParam) {
    case WM_PAINT: {
        PAINTSTRUCT ps;
        HDC hdc = BeginPaint(hwnd, &ps);
        
        // 每帧手动绘制所有内容
        draw_button(hdc, 50, 50, 100, 30, "Click");
        
        EndPaint(hwnd, &ps);
    }
}
现代自绘 (Win32 + Direct2D)
// 直接调用 DirectX 接口
ID2D1HwndRenderTarget* pRenderTarget;
ID2D1SolidColorBrush* pBrush;
void Render() {
    pRenderTarget->BeginDraw();
    pRenderTarget->Clear(D2D1::ColorF(D2D1::ColorF::White));
    
    // 直接绘制到 GPU
    pRenderTarget->FillRectangle(
        D2D1::RectF(50, 50, 150, 80),
        pBrush
    );
    
    pRenderTarget->EndDraw();
}

总结
问题	答案
窗口程序都调用渲染引擎吗？	是，只是引擎抽象层次不同
WPF/Avalonia 是怎么做的？	封装了 DirectX/OpenGL，提供高级 API
自绘引擎是什么？	跳过 UI 框架，直接调用图形 API
自绘=直接调 GPU 吗？	是，但也可以通过 GDI 等 CPU 渲染
哪个性能最好？	自绘 (DirectX/OpenGL) > 框架 > Electron
核心结论：
- 框架 = 帮你管理渲染细节，开发快，有 overhead
- 自绘 = 自己控制每一像素，性能高，开发慢
