  • Go的:=有几个含义:
    • 类型推导，省的我手写变量类型了
    • 强制变量使用，防止僵尸代码，至少用 _ = err来处理一下
    • 声明作用域，声明+赋值，会创造新的变量，如下面这个经典例子：

package main
import "fmt"
func main() {
    x := 1       // 声明一个外层变量 x
    if true {
        x := 2   // 又声明了一个新的内层变量 x！
        fmt.Println("内部 x:", x) // 输出：内部 x: 2
    }
    fmt.Println("外部 x:", x) // 输出：外部 x: 1（外层变量没有被修改）
}
  • 另外写的时候千万注意，x := xxx和x := xxx{}是不一样的，一个没有初始化默认nil，一个初始化了有默认值
  • Go和C#一样也用帕斯卡命名法来命名，但是更加极端，直接用首字母大小写来控制可见性：

2

首字母大写 = 公开（exported）  → Write, Server, Timeout
首字母小写 = 私有（unexported）→ write, server, timeout

这既是命名风格，也是访问控制。没有 public/private 关键字。 再就是根据变量的作用范围来调整命名长度，比如函数里用的局域变量一遍也就cnn,库里要用的连接字段则是Conn,靠上下文来表示代码含义…怎么这里你又不降低心智负担了喂

另外事后发现，Go的封装等级没有private一说，因为只有值类型struct没有class嘛，所以实际上Go只有public/interval两种封装级别

// Addr represents a network end point address.
//
// The two methods [Addr.Network] and [Addr.String] conventionally return strings
// that can be passed as the arguments to [Dial], but the exact form

type Addr interface {

	String() string  // string form of address (for example, "192.0.2.1:25", "[2001:db8::1]:80")
}

type slice struct {

    len  int       // 当前有几个元素

array [5]int:  ┌─────────────────────────────┐
               │  1  │  2  │  3  │  4  │  5  │  ← 这块堆内存是 array 的，它死了就回收
               └─────────────────────────────┘

slice []int:   ┌─────┬─────┬─────┐
               │ ptr │ len │ cap │  ← 16字节栈内存，放 ptr/len/cap
               └──┬──┴─────┴─────┘
                  │  指过去
                  ▼
               ┌─────────────────────────────┐
               │  1  │  2  │  3  │  4  │  5  │  ← 这块元素内存是底层数组的，slice 不管回收
               └─────────────────────────────┘

slice实际上是指向底层匿名数组的一个指针抽象 不过还有slice指向的数组当然不会被回收，不然slice就成了野指针了,所以记得用完了切片之后要slice = nil

  • 你以为这就完了吗？并没有，slice在Go语言里还实际上担任了动态数组的功能，因为底层的类型系统带上了长度，规定死了真-不可变长的数组，所以实际上需要用到动态数组的地方都会这么定义:
1
2
3
4
5

slice := make([]int,10)
slice = append(slice,4)
slice = append(slice,[]int{5,6})
// 头插性能太差，少用
slice = append([]int{0},slice)

在长度不够需要扩容的时候，实际上还是动了底层的匿名数组，扩容就创建个新的大小2倍的数组然后将旧数组的数据移过去 另外如果对slice做了扩容操作，超出了原有的数组长度，那么实际上会分配一个新的数组来让slice指向新数组，这时候你再对slice做的任何操作都不会指向原数组了，事实上，最佳实践就是用原数据的slice做处理，然后返回一个新的slice指向的数组，而不是直接修改原数据。这其实就是函数式的思想，不可变数据要求了元数据不可变，但是给你开放了可变的空间，靠规范来要求你不要动原数据，想动还是可以动的，而Rust就是更加激进的直接在编译器层面做了语法上的处理，如果你借用了不可变的数据但是内部动了会直接给你报错。 另外，Rust还限制同一时间只能存在一个可变引用，即同时只能存在一个slice指针或者能修改元数据的指针存在，以此保证编译期的内存安全。而Go是用GC来规避了这一切，在运行时会有GC来给乱玩指针的程序员兜底，这样保留了灵活性，也防止了悬空指针，不过数据竞争得程序员自己管了，Rust这些靠借用检查器在编译期就拦掉了。 我必须玩这个梗──但这一切值得吗？

  • Go的make传递的是引用项，是指针，但是在go里定义的chan传递的又是值拷贝，那么就会出现这样的情况：
1

type client struct{
	outgoing chan string
}
channel := make(chan client)
cl := client{outgoing: make(chan string)}
channel <- cl
channel <- cl
channel <- cl

这三个传递的cl是三个不同的值拷贝不错，但是outgoing是引用，所以它拷贝完了之后这三个传递的client实例的outgoing指向同一个底层的channel而不是三个

  • Go的goroutine是不是GC的可回收对象，一个正在阻塞等待channel的goroutine有引用根（活跃的栈），GC就不会回收它，所以如果因为什么写法导致一堆goroutine永久阻塞下去了，那么包括他们里面引用的上下文，buffer等都不会被释放。
  • Go语言里有这么个select关键字，专门用来处理channel，可以理解为处理channel的Switch，每次处理一个case就退出，所以一般搭配for循环来使用，内部实现用算法保证case被选中的概率是严格相等的，所以如果多个case都有消息，它会随机选一个执行

	select{
		case <- channel

type Message int
const(
	Disconnected Message = iota // 预定义标识符，每次在const里出现就重置为0

type MonitorCallback func(msg string)
type Assistant struct {

  • Do not communicate by sharing memory; share memory by communicating
    • 就是说，Go倾向于不直接在线程间共享一个全局的字段或者变量来通信，go更倾向于在不同的线程中各自维护自己的状态，然后通过线程安全的channel来传递

  • Go 的Json序列化反序列化匹配大小写不敏感
  • Go里有这么个设定interface{},叫空接口，默认所有的类型都自动实现它，也是是说传个什么都可以
  • <-chan xxx在Go里代表只读通道，chan<- xxx是只写通道，默认啥符号没有就是双向通道chan xxx
  • 如果之前没提到过，那么这里提一下，Go的goroutine并非真实线程，实际用户态线程，结构如下：
1
2
3
4
5
6
7

    G   G   G   G   G   G   G   G   G   G   G   G   G   G
     \  |  /       \  |  /        \  |  /        \  |  /
       P1             P2             P3             P4
       │              │              │              │
       M1             M2             M3             M4
       │              │              │              │
    CPU 核心 1     CPU 核心 2     CPU 核心 3     CPU 核心 4
缩写 全称 是什么 数量
G Goroutine 你的 go func() 创建的任务 成千上万，无限
M Machine / OS Thread 真正的操作系统线程 由 Go 调度器管理，通常等于核心数
P Processor 逻辑处理器 + 调度上下文 GOMAXPROCS 决定，默认 = CPU 核心数
这就是所谓的Go的G-M-P调度器模型，不过实际上的顺序是G-P-M-CPU，也有说法叫M:N调度器，即将M个goroutine映射到N个OS线程上运行
  • Go提供了一个神奇的语法糖，每个包可以写多个的func init(){},这个函数相当于提供给用户的重载，加载库的时候会自动执行，多个init的话就根据依赖关系顺序执行
