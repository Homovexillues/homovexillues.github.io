  • Go里有个常用概念，slice，其实就是C#里的Span<T>,C++里的std::span,一个指向内存地址的指针抽象，你传什么数组进来这个指针就指向什么数组，不过是这个数组里的一段连续内存，要在这个数据结构里指定好头和长度，大概是这样:

    slice实际上是指向底层匿名数组的一个指针抽象
    不过还有slice指向的数组当然不会被回收，不然slice就成了野指针了,所以记得用完了切片之后要slice = nil

  • 你以为这就完了吗？并没有，slice在Go语言里还实际上担任了动态数组的功能，因为底层的类型系统带上了长度，规定死了真-不可变长的数组，所以实际上需要用到动态数组的地方都会这么定义:

    在长度不够需要扩容的时候，实际上还是动了底层的匿名数组，扩容就创建个新的大小2倍的数组然后将旧数组的数据移过去
    另外如果对slice做了扩容操作，超出了原有的数组长度，那么实际上会分配一个新的数组来让slice指向新数组，这时候你再对slice做的任何操作都不会指向原数组了，事实上，最佳实践就是用原数据的slice做处理，然后返回一个新的slice指向的数组，而不是直接修改原数据。这其实就是函数式的思想，不可变数据要求了元数据不可变，但是给你开放了可变的空间，靠规范来要求你不要动原数据，想动还是可以动的，而Rust就是更加激进的直接在编译器层面做了语法上的处理，如果你借用了不可变的数据但是内部动了会直接给你报错。
    另外，Rust还限制同一时间只能存在一个可变引用，即同时只能存在一个slice指针或者能修改元数据的指针存在，以此保证编译期的内存安全。而Go是用GC来规避了这一切，在运行时会有GC来给乱玩指针的程序员兜底，这样保留了灵活性，也防止了悬空指针，不过数据竞争得程序员自己管了，Rust这些靠借用检查器在编译期就拦掉了。

  • Go的make传递的是引用项，是指针，但是在go里定义的chan传递的又是值拷贝，那么就会出现这样的情况： 这三个传递的cl是三个不同的值拷贝不错，但是outgoing是引用，所以它拷贝完了之后这三个传递的client实例的outgoing指向同一个底层的channel而不是三个
  • Go的goroutine是不是GC的可回收对象，一个正在阻塞等待channel的goroutine有引用根（活跃的栈），GC就不会回收它，所以如果因为什么写法导致一堆goroutine永久阻塞下去了，那么包括他们里面引用的上下文，buffer等都不会被释放。
  • Go语言里有这么个select关键字，专门用来处理channel，可以理解为处理channel的Switch，每次处理一个case就退出，所以一般搭配for循环来使用，内部实现用算法保证case被选中的概率是严格相等的，所以如果多个case都有消息，它会随机选一个执行
  • Go语言的枚举不存在对应关键字，底层用int实现，定义的时候需要这么做… 才怪！
    值得注意的是，Go语言的枚举类型用的是const约束，也就是说无论你定义在哪儿，最后在编译器层面是会铺开到同一层的，用法也是直接用定义的常量名，也就是这样： 项目里的枚举写得一多，根本没法自动补全，所以Go的枚举最佳实践目前是这样的： 把常量名带上枚举名的前缀，以便于自动补全…
    虽然我目前依然觉得这个设计还是够用就行，不过考虑到C#里那种顺滑的语法，不奇怪大家骂go语言的枚举实现很糟糕…
  • 卧槽了Go语言没有函数重载…为啥啊？？完全不必要的麻烦啊这个
  • go的args继承了C的传统，毕竟Go的设计者还是Ken Thompson、Rob Pike这老哥俩 所以记得用Go的参数的时候这么判断：

  • Go语言也继承了C语言的格式化语法
  • Go的核心思想就一句话，代码是给人读的，不是给人写的，你写起来巨难受的代码，比如显式处理错误，这样写起来很难受，但是你能没什么心智负担的看懂，不过这点我真的存疑，这种写法极大的增加了代码的码量，读起来真的能降低心智负担吗？
  • Go语言里的函数是一等公民，可以直接定义函数类型的变量或者参数： 其实就是用结构体包了一层，实际上的行为就是传了两个func(msg string)类型的函数参数到checkCPU函数里
  • Do not communicate by sharing memory; share memory by communicating
    • 就是说，Go倾向于不直接在线程间共享一个全局的字段或者变量来通信，go更倾向于在不同的线程中各自维护自己的状态，然后通过线程安全的channel来传递
  • Go 语言不支持任何的运算符重载
  • Go 的Json序列化反序列化匹配大小写不敏感
  • Go里有这么个设定interface{},叫空接口，默认所有的类型都自动实现它，也是是说传个什么都可以
  • <-chan xxx在Go里代表只读通道，chan<- xxx是只写通道，默认啥符号没有就是双向通道chan xxx
  • 如果之前没提到过，那么这里提一下，Go的goroutine并非真实线程，实际用户态线程，结构如下：
缩写 全称 是什么 数量
G Goroutine 你的 go func() 创建的任务 成千上万，无限
M Machine / OS Thread 真正的操作系统线程 由 Go 调度器管理，通常等于核心数
P Processor 逻辑处理器 + 调度上下文 GOMAXPROCS 决定，默认 = CPU 核心数
这就是所谓的Go的G-M-P调度器模型，不过实际上的顺序是G-P-M-CPU，也有说法叫M:N调度器，即将M个goroutine映射到N个OS线程上运行
  • Go提供了一个神奇的语法糖，每个包可以写多个的func init(){},这个函数相当于提供给用户的重载，加载库的时候会自动执行，多个init的话就根据依赖关系顺序执行
