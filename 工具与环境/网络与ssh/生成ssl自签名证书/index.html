生成SSL自签名证书

大部分Linux发行版配备了OpenSSL工具，可以用来生成自签名SSL证书，如果没有，sudo apt update && sudo apt install openssl 生成自签名证书的核心是使用 OpenSSL 的 req 命令。下面是创建一份通用的、可用于 HTTPS 服务器测试的证书的标准流程：

第1步：生成私钥（Private Key）

这是证书安全的基础，必须妥善保管。

1

openssl genrsa -out server.key 2048
  • genrsa: 生成 RSA 密钥对，密钥对里同时包含私钥和能推导出的公钥。
  • -out server.key: 将密钥对保存到 server.key 文件。
  • 2048: 密钥长度（位），2048 是目前安全与性能兼顾的标准。

第2步：生成证书签名请求（CSR - Certificate Signing Request）

CSR 包含了你的服务器和公司信息，用于向证书颁发机构（CA）申请签名。在自签名中，我们将用它直接生成证书。

1

openssl req -new -key server.key -out server.csr -subj "/C=CN/ST=YourProvince/L=YourCity/O=YourOrganization/CN=your-domain-or-ip"
  • req -new: 创建新的 CSR。
  • -key server.key: 使用上一步生成的密钥对，这里会自动提取出公钥来加密。
  • -out server.csr: 输出 CSR 文件。
  • -subj “/...”: 关键参数！ 用于预填所有信息，避免交互式提问。请替换其中字段：
    • C: 国家代码（如 CN 表示中国）。
      • ST: 州或省。
      • L: 城市。
      • O: 组织名称。
      • CN: 最重要的字段，必须填写你打算用此证书访问的域名或IP地址（例如 localhost、192.168.1.100 或 example.com）。如果 CN 与实际访问地址不匹配，浏览器会报安全错误。
        • 另：如果走反向代理等代理手段，这个IP写最外层的那个公网IP

第3步：生成自签名证书（CRT，即Certificate的缩写）

用自己的私钥为自己的 CSR 签名，这样就得到了自签名证书。

这里要提到一个签名的概念，所谓的签名，就是计算被加密内容的文件哈希，然后用私钥来加密这个哈希（公钥不能用来做签名，因为RSA密钥的数学性质，私钥能推算出公钥，但是反过来却不能)，并附加到要发送的数据包上，而一般发送的数据包会附带上公钥，用公钥可以对私钥进行解密，获取文件哈希，以此来对比文件是否被修改。

而这个逻辑依赖公钥不被修改，所以就有了CA用自己的私钥来加密的服务器公钥，作为CRT证书，这样确保公钥不被修改。

比如有中间人截获数据包，用你附带的公钥解密了签名，解密了数据包，拿到了session key，现在想全都换掉，完全没问题，但是他不能换成一个CA发的数字签名（CA攻击那另说），因为客户端会用CA签发方的公钥对数字签名做验证，不通过则浏览器就会提示有风险，做设备绑定数字签名的安全验证就会不通过

不过本文档的操作实际上是自签名，始终用的是服务器自己的密钥对，实际上为

1

openssl x509 -req -days 365 -in server.csr -signkey server.key -out server.crt
  • x509 -req: 使用 x509 标准处理证书请求。
  • -days 365: 证书有效期为 365 天。
  • -in server.csr: 输入 CSR 文件。
  • -signkey server.key: 使用私钥进行签名。
  • -out server.crt: 输出最终的证书文件。
