Systemctl

systemd单元文件的存放位置

路径 用途 管理方式 优先级
/usr/lib/systemd/system/ 发行版/包管理器安装的服务 由apt/rpm/yum管理 低（可被覆盖）
/etc/systemd/system/ 系统管理员配置的服务 手动创建/修改 高（覆盖/usr）
/run/systemd/system/ 运行时临时服务 系统运行时生成 临时（重启消失）
~/.config/systemd/user/ 用户级服务（用户会话） 用户管理 用户会话内
本段部分内容引用自systemctl服务文件管理指南 - huangSir-devops - 博客园

# /etc/systemd/system/myapp.service
# Systemd 服务配置文件示例
# 注释以 # 开头，可以出现在任何位置

[Unit]
# 单元描述和元数据
Description=My Application Service      # 服务描述（必填）
Documentation=https://example.com/docs  # 文档链接
After=network.target postgresql.service # 在哪些服务之后启动
配置 含义 适用场景
After=network.target 网络管理服务已启动 大多数需要网络的服务
After=network-online.target 网络真正连通（有可用的网络连接） 必须联网才能工作的服务
After=syslog.target 日志系统就绪后启动 需要记录日志的服务
After=multi-user.target 多用户模式就绪后启动 用户级服务

Before=nginx.service                    # 在哪些服务之前启动
Requires=postgresql.service             # 强依赖，如果这个服务失败，本服务也会失败

这里也可以依赖一些物理设备，如/dev下的设备都会在运行的时候动态生成虚拟文件，可以用systemctl status dev-ttyUSB0.device命令查看，这里也可以依赖这些虚拟文件，如 Requires = dev-ttyUSB0.device

Wants=network.target                    # 弱依赖，希望但不必须,如果依赖挂了本服务也可以运行
Conflicts=old-app.service               # 冲突的服务

# 服务启动条件
ConditionPathExists=/opt/myapp/config.json    # 文件必须存在
ConditionDirectoryNotEmpty=/opt/myapp/data    # 目录不能为空
AssertPathExists=/opt/myapp/myapp             # 断言可执行文件存在

[Service]
# 服务类型
Type=simple
Type 进程行为 适用场景 是否需要 PIDFile
simple 简单类型（默认）,前台运行，不 fork,ExecStart 是主进程 现代应用、微服务 否
forking 分支类型，主进程会 fork 子进程后退出 传统守护进程 是
oneshot 一次性，进程退出后服务就停止 初始化脚本 否
dbus 注册 D-Bus 服务,通过 D-Bus 名称获取启动状态 桌面服务 否
notify 通过 sd_notify() 通知 systemd 启动完成 现代应用 否
idle 延迟启动 低优先级任务 否

# 执行命令
User=appuser                                # 运行服务的用户
Group=appgroup                              # 运行服务的组
WorkingDirectory=/opt/myapp                 # 工作目录
ExecStart=/opt/myapp/myapp --config /etc/myapp/config.conf  # 启动命令
ExecStartPre=/bin/bash -c 'echo "Starting service at $(date)"'  # 启动前执行的命令
ExecStartPost=/bin/bash -c 'echo "Service started at $(date)"'  # 启动后执行的命令
ExecReload=/bin/kill -HUP $MAINPID         # 重载配置的命令
ExecStop=/bin/kill -TERM $MAINPID          # 停止服务的命令
ExecStopPost=/bin/bash -c 'echo "Service stopped at $(date)"'   # 停止后执行的命令

# 环境变量
Environment=NODE_ENV=production            # 设置环境变量
Environment=DB_HOST=localhost DB_PORT=5432 # 多个环境变量
EnvironmentFile=/etc/myapp/environment     # 从文件加载环境变量

# 资源限制
LimitNOFILE=65536                          # 最大文件描述符数
LimitNPROC=4096                            # 最大进程数
LimitCORE=infinity                         # 核心转储大小限制

# 进程行为
Restart=always                             # 退出时总是重启
# Restart=on-failure                       # 仅在失败时重启（非零退出码）
# Restart=no                               # 不自动重启
RestartSec=10                              # 重启前等待时间（秒）
StartLimitInterval=300                     # 启动频率限制时间窗口
StartLimitBurst=5                          # 在时间窗口内允许的启动次数

# 安全设置
NoNewPrivileges=true                       # 禁止获取新权限
ProtectSystem=strict                       # 保护系统目录
ProtectHome=true                           # 保护家目录
PrivateTmp=true                            # 使用私有临时目录
ReadWritePaths=/var/lib/myapp             # 允许写入的路径

# 超时设置
TimeoutStartSec=30                         # 启动超时时间
TimeoutStopSec=30                          # 停止超时时间

[Install]
# 安装选项 - 定义如何启用服务
# ===== 基础安装配置 =====
WantedBy=multi-user.target          # 关联到标准多用户目标（开机自启）
RequiredBy=critical-services.target # 强依赖目标（必须随该目标启动）
Also=myapp-socket.service           # 关联的其他单元（同时启停）
Alias=legacy-app.service            # 服务别名（兼容旧名称）
 
# ===== 多实例服务 =====
DefaultInstance=http               # 默认实例名称（用于模板单元）
WantedBy=app-instances.target       # 多实例关联目标
 
# ===== 反向依赖控制 =====
WantedBy=postgresql.service         # 反向声明：当 postgresql 启用时自动启用本服务
RequiredBy=nginx.service            # 反向强依赖（不推荐，易导致循环）
 
# ===== 高级生命周期 =====
StopWhenUnneeded=yes                # 当无其他依赖时自动停止（需配合 RefuseManualStart）
RefuseManualStart=no                # 是否允许手动启动（默认 no）
RefuseManualStop=no                 # 是否允许手动停止（默认 no）
 
# ===== 触发式安装 =====
Upholds=myapp-monitor.timer         # 当 timer 激活时自动维护本服务状态

Systemd-Networkd

用于配置网络，需要在/etc/systemd/network下配置一个.netdev文件和一个对应的.network配置文件,配置之后重启生效sudo systemctl restart systemd-networkd

2
3
4

# dummy0.netdev
[NetDev]
Name=dummy0
Kind=dummy
1
2
3
4
5

# dummy0.network
[Match]
Name=dummy0
[Network]
Address=10.100.0.1/24

对于它和Linux的netplan的优先级问题，设定是这样的： 在 Ubuntu 24.04 上，Netplan 是官方唯一支持的“持久化网络配置”入口，优先级>systemd文件；
/etc/netplan/*.yaml 里的内容最终会被 netplan generate 动态翻译成/run/systemd/network/*.network/*.netdev 等临时文件，再交由 systemd-networkd（或 NetworkManager）执行
