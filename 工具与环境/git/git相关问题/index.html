Git的使用流程是啥？

Git 的三个区域

Git 的工作流程涉及三个核心区域：

  1. 工作区 (Working Directory) — 你实际编辑文件的地方
  2. 暂存区 (Staging Area / Index) — 一个"待提交"的缓冲区
  3. 仓库 (Repository) — 提交后的永久记录 正常的 Git 流程是：
1

编辑文件 → git add（放到暂存区）→ git commit（提交到仓库）→ git push（推送到远程）

为什么要分两步（add + commit）？

暂存区的作用是让你精确控制哪些改动属于同一次提交。比如你改了 5 个文件，但其中 3 个是一组逻辑改动，另外 2 个是另一组，你可以分两次 git add + git commit，让每次提交都干净、有意义。

为什么你之前"直接提交推送"？

大概率是你用的工具（或配置）在背后自动帮你执行了 git add . + git commit + git push。很多封装工具为了简化操作会：

  • 自动把所有改动 git add -A（全部暂存）
  • 自动生成 commit message 并提交
  • 自动 push 这样你感觉是"直接提交推送"了，但底层流程其实没变，只是工具替你做了 add 那一步。

常见的 Git 工具流对比

方式 流程 灵活度
原生 Git CLI 手动 add → commit → push 最高，完全可控
VS Code / IDE 可选择性暂存文件，然后提交 高
GitHub Desktop 选择文件提交，自动 add 中
一键式工具/脚本 全部自动 add + commit + push 最低，但最省事

实用建议

如果你想要精细控制但又不想每次手动 add，可以用：

1
2
3

git add -A && git commit -m "msg"   # 全部暂存+提交（一步到位）
git commit -am "msg"                  # 等价于上面（但不包括新文件）
git commit -am "msg" && git push      # 全自动

但如果你想要更好的提交历史，建议保持 add + commit 分开，这样每次提交的内容更有意义，出了问题也更容易回退。

.git/
├── HEAD                    # 指向当前所在的分支
├── config                  # 项目特定的Git配置
├── description             # 仓库描述
├── index                   # 暂存区（staging area）索引
├── hooks/                  # 客户端和服务端钩子脚本
├── info/                   # 全局排除文件和稀疏检出配置
│   └── exclude
├── objects/                # 所有Git对象存储（核心！）
│   ├── info/
│   └── pack/               # 打包压缩的对象
│       ├── pack-xxx.pack   # 打包的数据文件
│       └── pack-xxx.idx    # 打包的索引文件
├── refs/                   # 引用（分支、标签等）
│   ├── heads/              # 分支引用
│   ├── tags/               # 标签引用
│   └── remotes/            # 远程跟踪分支
└── logs/                   # 引用更新日志

Git的配置存在哪里？

① 全局配置（整台电脑通用）

  • Windows：C:\Users\你的用户名\.gitconfig
  • Mac/Linux：~/.gitconfig 可以通过此命令设置：
1
2

git config --global user.name "张三" 
git config --global user.email "zhangsan@xxx.com"

② 单个仓库本地配置（只对当前项目生效）

在你的项目文件夹里：

1

项目根目录/.git/config

此命令只设置单个当前仓库的配置:

1

git config user.name "项目专用名字" git config user.email "项目专用邮箱"
